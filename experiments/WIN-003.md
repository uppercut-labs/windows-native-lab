# WIN-003 - Media Desk

## Purpose

MediaPlayer playback, System Media Transport Controls and native lifecycle recovery.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Actual supported MediaPlayer/SMTC APIs, a local output device and a small provenance-recorded public or synthetic media fixture. Network playback is a separate live case, not a dependency of domain tests.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read playback/transport support and endpoint presence; report codec/source failures explicitly. Inventory is not evidence of audible playback.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

Show a clear playback unavailable/retry state and retain browse/session controls. A simulated transport is labeled test-only and never sold as actual media.

## Bounded experiment

Play one bounded fixture, seek/pause/resume, switch to one live public test stream if available, then exercise minimize, navigation, endpoint disconnect and sleep/wake. Maintain one audible owner and safe SMTC metadata.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Buffering; failed URI; unsupported media; duration unknown; source ending; duplicate key event; OS SMTC changes; minimize/close; endpoint removal; stale metadata.

## Acceptance and evidence

W0 covers owner and session rules. W1 compiles. W2 tests a labeled fake transport. W3 inspects native player states. W4 proves audible fixture/live playback and recovery with actual process costs. W6 covers endpoint/media-key/sleep behavior on real hardware.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
