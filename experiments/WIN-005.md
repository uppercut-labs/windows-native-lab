# WIN-005 - RTX Model Bench

## Purpose

Compare supported Windows ML/ONNX, optional TensorRT and CPU execution with real correctness/resource receipts.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Pinned inference packages and an explicitly acquired small public/synthetic model with license/hash/version. Optional NVIDIA provider requires verified runtime/driver/architecture compatibility. NPU/RTX naming is insufficient.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read provider readiness and model requirements. Actual provider placement is inspected during a bounded inference run, not assumed from device enumeration. Report missing model/provider separately.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

Measured CPU inference when useful, or deterministic non-model functionality. No large model download or GPU requirement at launch.

## Bounded experiment

Run a fixed synthetic input set through CPU and each available accelerator; compare outputs/tolerances, warm/cold latency, peak memory/VRAM, cancellation and unload. Downloads require explicit size-disclosed action.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Missing asset; invalid hash; incompatible operator; CPU fallback; out-of-memory; cancelled initialization/inference; provider unavailable; repeated runs; unload releases memory.

## Acceptance and evidence

W0 tests input/asset/provider guards. W4 validates output against CPU reference using a monotonic measurement method. W6 traces actual placement and named driver/provider costs. Stub responses are never inference evidence; unsupported TensorRT/NPU paths stay unqualified.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
