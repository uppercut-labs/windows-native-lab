# WIN-004 - Audio Workshop

## Purpose

Bounded AudioGraph/WASAPI experiments, endpoint selection and measured audio recovery.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Supported Core Audio/AudioGraph APIs and real endpoints. Exclusive/low-latency/loopback paths are independent opt-in experiments; no driver or system-default change is required for baseline shared-mode playback.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read endpoint availability and supported formats; qualify graph/tap/loopback availability through a bounded explicit run. Product naming does not prove latency or fidelity.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

System-selected shared-mode playback, with unavailable custom routing plainly marked.

## Bounded experiment

Play a synthetic tone/file through shared mode; explicitly choose a device; test one read-only analysis path where supported; measure latency with a declared method. Never alter the reference recording or seize another application's output.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Hot-plug; unsupported format; device busy; graph creation failure; cancellation; clipping detection; source/sample-rate mismatch; resource release; exclusive mode rejection.

## Acceptance and evidence

W0 verifies format/buffer bounds and read-only FFT synthetic tones. W4 records actual audio operation and trace costs. W6 names endpoint/driver/mode/format and measured latency method. Bit-identical pass-through is tested where the architecture claims it; no lossless/spatial-master inference.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
