# WIN-012 - MIDI Workshop

## Purpose

Isolated MIDI device/input/output preview with safe typed action mappings.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Verify current official Windows MIDI Services SDK/runtime/preview availability and device prerequisites on the actual host. MIDI 2.0 support is not inferred from the presence of a MIDI port.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read supported services/devices and advertised protocols without emitting output or opening an uncontrolled session. Separate virtual-device readiness from physical-device timing.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

Keyboard/controller/native controls perform the same actions; the MIDI feature remains unavailable when runtime/device prerequisites fail.

## Bounded experiment

In an isolated preview app, map a bounded input set to synthetic transport/selection actions. Output/feedback/clock is a separate explicit action with selected destination, rate/cap limits and stop/disconnect handling.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

No service; no device; wrong protocol; hot-plug; permission failure; malformed/rapid input; lost connection; cancel output; duplicate command; no output on launch.

## Acceptance and evidence

W0 tests parsing/mapping/bounds. W2/W3 prove native action fallback. W6 records actual runtime/version/port/protocol and input/output physical behavior. Virtual MIDI results stay labeled. No rollout date or production readiness is promised from an announcement.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
