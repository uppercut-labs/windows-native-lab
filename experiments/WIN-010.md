# WIN-010 - Capture & Render

## Purpose

Explicit Windows capture, GPU rendering/encoding and resilient media export.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Currently supported capture consent/selection APIs and optional hardware encode path; synthetic public assets. Encoding/capture hardware path is qualified separately from render initialization.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read capture/codec/encode support and storage limits without prompting or recording. Only an explicit capture operation selects a source and starts capture.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

Foreground software export or a queued explicit offline job; do not claim GPU acceleration if unavailable.

## Bounded experiment

Render a short synthetic scene into a small video; optionally explicitly capture one selected sample window; checkpoint/cancel/resume and atomically publish final output. Never capture unrelated desktops/sources.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Capture permission denied; source closes; codec unavailable; cancellation at publish boundary; disk full; process interruption; invalid checkpoint; partial output; GPU device loss.

## Acceptance and evidence

W0 covers jobs/atomic publish/cancel logic. W4 inspects decoded output/audio/duration and resource traces. W6 verifies actual encoder/capture path and consent. Partial files never replace good output; output completion and remote transfer are distinct receipts.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
