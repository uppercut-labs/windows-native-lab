# WIN-002 - Surface Deck

## Purpose

Native tray/taskbar controls, opt-in notifications and optional Windows widgets.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

A supported native desktop shell. Notifications and widgets may require identities, host/service availability or runtime features; verify current official requirements before choosing those surfaces.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read notification support/permission and widget host/runtime readiness; determine available taskbar/tray surface support. Probes never grant permission, register a provider or change startup settings.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

A compact native window contains the same actions and state when a system surface is unavailable.

## Bounded experiment

Expose play/pause of a simulated session and open-item actions in tray/taskbar. Send one explicit test notification with a typed activation target. Optional widget uses a tiny synthetic snapshot and is isolated from baseline.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Denied notification permission; absent widget host; repeated activation; stale snapshot; app restart; taskbar recreation; multiple identities; high contrast.

## Acceptance and evidence

W0 tests snapshot/action filtering. W2/W3 inspect tray/taskbar/notification layout and routes. W5 records exact identity and registration. W6 names system host behavior separately from a fixture render; missing widgets are honestly unavailable.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
