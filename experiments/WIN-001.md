# WIN-001 - Shell Atlas

## Purpose

Typed native actions, URI activation, jump lists and existing-instance routing.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

A supported Windows desktop build and pinned Windows App SDK/WinUI 3 shell. Package identity and activation behavior are qualified independently for packaged and unpackaged modes.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Inspect actual package/AUMID/protocol registrations and running instance keys without changing them. Detect supported activation kinds. Reject malformed or cross-identity routes.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

The same typed actions remain available in an in-app command palette and ordinary controls.

## Bounded experiment

Implement five synthetic actions over a fixed catalog: open item, show collection, toggle fixture playback, start fixture station and show settings. Route one URI and one jump-list destination to an already-running native window. All sample identities/routes are isolated.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Malformed arguments; nonexistent item; duplicate activation; cold versus warm activation; two independent identities; unknown action; no unintended second window.

## Acceptance and evidence

W0 validates routes/action arguments and deduplication. W1 builds a pinned native target. W2/W3 inspect native cold/warm routing and keyboard focus. W5 verifies registered identity, jump-list behavior and that unrelated associations/processes remain untouched.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
