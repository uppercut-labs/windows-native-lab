# WIN-008 - Search & Activation

## Purpose

Qualified Windows indexing/search routes, native deep links and document/file activation.

This file is a specification. It does not assert that the experiment is
implemented, shipped, installed or hardware-qualified.

## Requirements

Supported documented Windows search/indexing/activation APIs and isolated package/file identity. This lab does not promise system search parity with another operating system.

Verify current official SDK/API deployment floors before selecting dependencies.
Pin the actual toolchain and keep optional/preview requirements isolated.

## Runtime probes

Read supported index/search/association routes and actual package readiness without taking over existing associations. Runtime/API availability and privacy scope are explicit.

Publish a `CapabilityReadiness` reason and fallback. Readiness probes never
prompt, download, start recording/listening/output or alter system settings.

## Meaningful fallback

Native in-app search, exact-link paste and open-file dialog route to the same typed router.

## Bounded experiment

Index or expose a bounded synthetic item set using a currently documented supported route; prove activation where possible. Register one isolated document extension and preview an offline synthetic document after explicit install/consent.

Bind operations to IDs and exact request fingerprints. Use bounded memory/time,
explicit cancellation and honest failed/rejected outcomes. Do not publish partial
output or silently replay a side effect on a duplicate request. The foundation's
in-memory ledger is not a durable/network exactly-once guarantee.

## Fault and transition cases

Unavailable indexing route; index stale; missing item; malformed URI/file; unknown schema; excessive size; duplicate activation; association belongs to another app.

## Acceptance and evidence

W0 tests router/import validation. W2/W3 prove app search/preview fallback. W5 records actual association/activation identity. W6 verifies actual Windows search result routing where supported. A screenshot of in-app results does not qualify OS search.

Record exact commit/toolchain/architecture/package when relevant, fixture and
asset provenance/hash, capability state, operation IDs/outcomes, commands,
inspected captures, measured costs and unverified paths. Measurements use actual
operations and monotonic clocks/profilers, not replay timestamps. Sanitize receipts;
raw inventories/captures/models remain ignored. Never include account/host/user
identity, serials, credentials or confidential consumer content.
